# Dominio Inmopro (CRM lotes)

- La aplicación gestiona **proyectos inmobiliarios**, **lotes**, **clientes**, **asesores**, **comisiones**, **cuotas**, **tickets de atención** y flujos como pre-reservas y confirmación de transferencias.
- Los textos de interfaz y mensajes al usuario deben ir en **español** salvo que el código existente use otro idioma de forma explícita.
- El estado **TRANSFERIDO** puede registrarse desde la vista de proyecto (`/inmopro/projects/{id}`) solo desde **RESERVADO**, con **fecha de escritura** (`notarial_transfer_date`) obligatoria y liquidación de saldo (`advance = price`, `remaining_balance = 0`); también existe el flujo con evidencia en **confirmación de transferencia** (`LotTransferConfirmation`).
- Al registrar una transferencia (`LotTransferConfirmationController::store`) se confirma **quién transfiere** (`payer_name` obligatorio, `payer_dni` opcional; puede ser distinto al cliente que reservó) y se adjuntan **uno o más comprobantes** (`LotTransferVoucher`: imagen, banco de `LotTransferVoucher::BANKS` u `OTRO` con texto, monto y n.º de operación). El monto de transferencia es independiente de la suma de comprobantes. Banco + n.º de operación no puede repetirse en otra transferencia no rechazada. `evidence_path` queda solo para transferencias antiguas.
- **Historial del lote** (`lot_histories`, `LotHistory`): `App\Observers\LotObserver` registra creación y cambios de estado/cliente/asesor; el evento se deduce de la transición (PRERESERVADO, RESERVADO, TRANSFERIDO, LIBERADO, VENTA_CAIDA, etc.). Para agregar motivo, notas o datos extra, envolver el `update` en `LotHistoryRecorder::withContext([...], fn () => ...)`. Usar siempre actualizaciones vía modelo (no `->lot()->update()` de query builder) para que el observer registre el cambio. Si actúa un asesor (CRM/Cazador), `user_id` queda null y `user_name` lleva su nombre.
- **Liberar lote** (`POST inmopro/lots/{lot}/release`, `LotReleaseService`): solo desde RESERVADO o CUOTAS y sin abonos registrados; elimina cuotas/cronogramas, limpia cliente, asesor y datos de venta, pasa a LIBRE y guarda la foto de la venta en el historial (VENTA_CAIDA o LIBERADO) y en auditoría (`lots.released`).
- Las comisiones se generan vía `App\Services\Inmopro\CommissionService::createCommissionsForTransferredLot` en cuanto el lote pasa a TRANSFERIDO (al registrar la transferencia con evidencia, al aprobarla o desde proyecto), si el lote tiene asesor con nivel y aún no tiene comisiones. La fecha de la comisión es la fecha de escritura (`notarial_transfer_date`). Si la transferencia se rechaza, se eliminan las comisiones PENDIENTE del lote. `php artisan inmopro:sync-transferred-lot-commissions` genera las faltantes de lotes ya transferidos.
- En **API Cazador**, los **recordatorios** (`ReminderController`) solo aplican a clientes del asesor con tipo **`PROPIO`** (misma regla que tickets de atención y pre-reservas).
- **DNI** y **teléfono** de cliente son **únicos en todo el sistema** al crear o actualizar (Inmopro web y API Cazador). Si hay conflicto, el mensaje indica el vendedor que registró al cliente existente (`ClientDuplicateRegistrationChecker`).
